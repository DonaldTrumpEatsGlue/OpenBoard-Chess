# Openboard Chess

Openboard is an original, local-first chess app. It is not affiliated with Chess.com.

## Run it

On Windows, double-click `start-openboard.bat`. It locates Node.js and npm even when `npm` is not on `PATH`, runs the install with Windows Command Prompt as npm's script shell, starts the local online-room server if it is not already running, and waits for the website before opening `http://127.0.0.1:5173/`. The website and room server run in separate windows; stop them with Ctrl+C in their windows. Node.js with npm must be installed.

## Publish as a website with GitHub Pages

The prepared `Openboard-GitHub-Pages` folder is a separate, ready-to-publish copy of the source project. With GitHub Desktop, choose **File → Add Local Repository**, select that folder, then click **Publish repository**. After publishing, open the repository's **Settings → Pages** and set the build and deployment source to **GitHub Actions**. The included workflow builds and deploys automatically whenever you push to `main`; GitHub displays the website URL under **Settings → Pages**.

The installed root and server `node_modules` folders are included in this repository as requested. GitHub Actions still runs `npm ci` to install platform-appropriate dependencies before building and testing.

Gameplay, saved settings, custom pieces, and the computer opponent run in each visitor's browser. GitHub Pages is static hosting, so friend-online rooms also need the separately hosted WebSocket service described below.

For a standalone Windows x64 desktop installer, double-click `build-openboard-desktop.bat`. The installer is written to `release/Openboard Chess Setup 1.0.0.exe`; the installed game does not require Node.js. The first installer is about 350 MB because it includes Electron and the full Stockfish engine. It is not code-signed, so Windows may show its standard unknown-publisher warning. Building it requires internet access to download packaging tools.

Run `npm run test:custom-chess` to check custom move generation, captures, attacks, mirroring, undo, and promotion. Run `npm run test:large-board` to check the expanded board rules.

The page also opens directly from `index.html`, but browser security can prevent Web Workers from running on `file://`; use the local server or desktop build for the worker-based opponent. Player profile search is a dedicated page, and account country badges use an approximate signup-time GeoIP lookup performed locally by the online server; the address is not sent to a third party or stored. VPNs, proxies, and unknown addresses can produce a missing or inaccurate country, and accounts created before this feature may have no country badge.

## Friend games

The Windows app launcher starts the room server automatically. Otherwise start it with `start-openboard-online-server.bat` or `npm run online-server`; it listens on port 3001. The online server requires Node.js 24 or newer. The Windows launcher installs the server-only dependencies from `server/package-lock.json` the first time they are needed. For a fresh checkout when running `npm run online-server` directly, install them once with `npm ci --prefix server`. Online play requires an Openboard account. Usernames are claimed uniquely when an account is created and cannot be changed through the game client. If Supabase email confirmation is enabled, new players verify using the email link and then sign in; if it is disabled, signup signs in immediately. Players should use an email address they control for account recovery. The website connects to its configured room server automatically; players never need to paste a server URL. The **Online** button opens lobby controls independently of account creation; unauthenticated players can open the separate **Sign Up** or **Log In** screen from the menu or Online prompt. Each signed-in account can have one active player room at a time; repeated create requests are rejected instead of leaving duplicate lobbies behind. Create a lobby with a name, optionally enable a lobby password, or join by invite code. Public lobbies remain visible in the list to their players, but a player cannot join or spectate their own game; other signed-in users can join or watch when available. The spectator total appears on each lobby card and next to the board while an online game is active. Choose **Watch** from the public-room list to spectate in one click when no password is set; watching does not take a player slot. Use **Watch game** with an invite code to spectate private games as well; password-protected rooms still require their password. When an opponent disconnects or refreshes, the remaining player gets a popup to wait or return to the main screen. Public lobbies remain listed during the reconnect window, and the same account can reclaim its reserved player seat with the current position while another player remains connected. A different player can take a disconnected seat; doing so starts a new game from the initial board. If both players leave or disconnect, the empty lobby is removed and cannot be rejoined. The last invite code is also saved in the Online panel for private-room rejoining. Online rooms have separate Players chat and Spectator chat boxes; players and spectators can read both, while each group can post in its own chat. Either player can request a local move suggestion at any time during an active online game; the suggestion is for the side to move and is not sent to the opponent. Spectators cannot request suggestions. The server checks every access token with Supabase Auth, loads the reserved username, and validates every chess move before relaying it.

In both computer games and online rooms, players can queue a premove during the opponent's turn; it is played automatically if it remains legal after the reply, and can be canceled by clicking its source or destination. Online rooms support two players in standard chess, plus spectators. The public browser lists rooms on this server; it is not a global directory across unrelated servers. Room state is held in server memory; empty rooms are removed immediately, and rooms with a disconnected player expire 30 minutes after their latest activity or disconnect. Clocks, draw offers, ranked matchmaking, and persistent game history are not implemented.

## Friends, messages, and notifications

The bottom of the navigation sidebar contains separate Friends, Messages, Notifications, and Settings buttons. Signed-in players can search for accounts by username, send or respond to friend requests, and exchange private messages with accepted friends. Friend requests and unread-message counts also appear as notifications and badges on the sidebar buttons. Settings in the sidebar are synchronized with the existing board theme, interface theme, and move-sound controls. Social data is stored in Supabase; the online server authenticates every request and uses its private service-role key to call the social database functions. Direct access to friend and message tables is disabled for browser users. Deployments must apply the current [`supabase/schema.sql`](./supabase/schema.sql) and configure the online server's Supabase service-role key.

### Deploy online rooms for GitHub Pages

The repository includes a free Render web-service Blueprint in `render.yaml`. A free Supabase project provides accounts and durable username claims; visitors do not need Render or Supabase accounts. The owner does need to connect this GitHub repository to Render and configure one Supabase project. Free hosts have availability limits, but Supabase pauses inactive free projects rather than deleting accounts at 30 days.

1. Create a free Supabase project. In its SQL Editor, run [`supabase/schema.sql`](./supabase/schema.sql). Re-run this script after updates; it changes the profile trigger so usernames and signup country codes are saved as soon as the account is created, installs online rating fields and the server-only rating settlement function, and creates the protected friends, friend-request, and direct-message tables and RPC functions.
2. Set the Supabase Site URL and allowed redirect URL to `https://donaldtrumpeatsglue.github.io/OpenBoardChess/`.
3. In Supabase, open **Authentication → Sign In / Providers → Email** and choose whether to enable **Confirm email**. With confirmation enabled, the app sends a verification link and directs new players back to sign-in; configure custom SMTP for reliable delivery to public users because Supabase’s built-in sender is restricted to project-team addresses. With confirmation disabled, signup signs in immediately without SMTP.
4. Copy the Supabase Project URL and the browser-safe **anon/publishable** key. Keep the `service_role` or secret key private. Configure Supabase email SMTP if you want account verification and password-reset emails to reliably reach public users.
5. In Render, create a **Blueprint** for this GitHub repository. Render reads `render.yaml` and deploys the Node room server. Set its `SUPABASE_URL`, `SUPABASE_ANON_KEY`, and `SUPABASE_SERVICE_ROLE_KEY` environment variables. The service role key is required for private username-to-email lookup during username sign-in, saving authoritative online rating results, and serving authenticated social requests; it stays on the server and must never be added to GitHub variables, the website, or client code. The service name in the Blueprint configures the website's default room-server address.
6. In GitHub **Settings → Secrets and variables → Actions → Variables**, add `SUPABASE_URL` and `SUPABASE_ANON_KEY` with the public values from step 4. Never add the service role key to GitHub Actions variables. `OPENBOARD_SERVER_URL` is optional; the workflow defaults it to `wss://openboard-online.onrender.com/ws`.
7. Push a commit to `main`, or run **Actions → Deploy Openboard to GitHub Pages → Run workflow**. The Online panel then connects automatically with no server-URL field. In **Settings → Pages**, use **GitHub Actions** as the source.

Your visitors only need an Openboard account: username, email, and password. They can sign in using either their email or username with the same password. Username sign-in and username password recovery require `SUPABASE_SERVICE_ROLE_KEY` on the online server; email sign-in continues to use Supabase directly. Use **Forgot password?** in the sign-in form with either the account email or username to send a six-digit recovery code to the linked account email, then enter the code and choose a new password. To enable code recovery, set the Supabase password-recovery email template to include `{{ .Token }}`; recovery links are also supported. Email ownership is verified only when the Supabase project has confirmation enabled. Their account reserves the username, and the game server ignores client-supplied display names. The hamburger menu provides separate **Sign Up** and **Log In** actions; **Online** opens lobby controls independently. To create a lobby, a signed-in player enters a **Lobby name** and optionally enables a **Lobby password**. Password-protected public lobbies remain listed, but joining requires their password. Country flags are shown beside account names in profiles, lobby listings, active games, and chat when signup-time GeoIP data is available; this is approximate location metadata and can be affected by VPNs or proxies.

After a lobby is created, the Online menu closes and the game screen provides **Disconnect & return to main screen**. Leaving asks for confirmation, then explicitly releases your lobby connection so you can create or join another room. Browsers also warn before navigating away from an active online room.

The free Render room server sleeps after inactivity; its first wake can take about a minute, and open games are lost if it sleeps or restarts. Free Supabase projects pause after one week without activity, but their account data is retained and can be resumed by the owner. Free hosting cannot guarantee uninterrupted, always-on service. The Render Blueprint permits `*.github.io` origins; for a custom Pages domain, add its exact origin to `OPENBOARD_ALLOWED_ORIGINS`.

Run `npm run test:online` to test public room listing, private-room exclusion, and joining a listed game.

## Current features

- Legal chess, move notation, promotion, check, and draw detection via chess.js.
- Editable custom rules for no-draw games and configurable pawn, knight, bishop, rook, and queen movement. Each standard piece's movement can be assigned to White, Black, or both sides, with separate movesets per side; select multiple standard movement patterns to make compound movers such as rook-knights.
- Custom game pieces are created and named in Custom Piece Studio, then selected in Custom Rules to replace a non-king piece type for both sides or one side. The rules dialog only assigns saved Studio pieces; it no longer has a second piece editor.
- Custom settings persist locally and apply to both player moves and bot move generation on the next game.
- Custom Rules offers vanilla 8×8 plus playable 10×10, 12×12, 14×14, 16×16, 18×18, and 20×20 boards. Larger boards keep the classic eight-piece setup centered, symmetrically add knights, bishops, rooks, then queens, and place a pawn on every file. They use the local rules-aware bot (not Stockfish), and online rooms and the built-in puzzle remain 8×8 only.
- Sixty-three original opponent profiles with varied Stockfish skill/time presets and style labels; displayed strength is explicitly not Elo.
- Stockfish 19 full, single-threaded WebAssembly in a Web Worker for orthodox games, plus a separate MAX ENGINE profile that removes skill limits; custom-movement games remain on the rules-aware local search.
- A local Custom Piece Studio with a clickable relative-square movement editor, step/slide/leap preview, per-vector move/capture/attack behavior, mirroring, rotation, range, undo/redo, a blocker sandbox, and persistent JSON import/export. Saved non-royal definitions can be added to full games and use their Studio movement rules directly.
- Click-to-move and drag-and-drop, legal-move indicators, move history, undo/redo, board flip, and both playing colors.
- Opening and move notes for both sides, with curated opening-name/theme recognition and Book, Best, Excellent, Good, Great, Brilliant, Inaccuracy, Mistake, or Blunder tags in the move list.
- Player profiles searchable by username, with separate estimated offline and online Elo and win/draw/loss records. Online estimates start provisional at 1000 and update after completed online games; offline estimates start at 1000 and are saved per account in the local browser.
- Optional clocks, board and interface color themes, supplied local MP3 sound effects, per-event previews and controls, and saved preferences.
- A mate-in-one puzzle, FEN and PGN loading, PGN export, and a basic analysis suggestion.

## Engine and rating notes

Orthodox games use Stockfish.js 19 full WebAssembly. Regular opponent profiles set Stockfish's supported `Skill Level` option and use different time limits; these settings are not calibrated ratings. MAX ENGINE uses the full build at Skill Level 20 with no Elo limiter, 256 MB hash, and up to 30 seconds per move, subject to the device's performance. The full single-threaded WebAssembly network is about 94 MB and is requested only when the engine is started. It avoids requiring cross-origin-isolation headers, but will take time and bandwidth to download. Search depth, node count, and nodes per second are shown while it thinks.

The Stockfish engine is distributed under GPL-3.0. Its license is copied alongside the engine in production builds at `dist/stockfish/Copying.txt`; the corresponding Stockfish.js source is available from the [Stockfish.js 19.0.1 release](https://github.com/nmrugg/stockfish.js/tree/v19.0.1).

Bot profiles have not been calibrated through match testing, so no profile is presented as having a verified Elo rating. The offline estimate uses the selected bot's unverified preset strength; online estimates use an Elo-style K=32 update against an initial 1000 rating. Neither is official or externally verified. Online profile ratings are public; offline ratings are stored only in the browser and shown only on the signed-in owner's profile on that device. The profiles are engine skill/time presets, not adaptive player models. Opening names and plans use curated common lines plus a general first-move classifier, so offbeat positions still receive a useful family label and plan without being misrepresented as a known book variation. Move grades use a quick material-and-position estimate so moves on either side can be annotated immediately; they are estimates, not official ratings or full Stockfish analysis. Custom-movement games use the app's separate, less capable variant search, not Stockfish.

The Stockfish build requests a WebAssembly file matching its worker script name (`stockfish-19-single.wasm`); the build ships this exact sibling asset in development and production.

The chess.js rules library and Stockfish engine are bundled locally. Google web fonts are optional and require internet access; the app falls back to local system fonts when offline. The online service supports accounts, rooms, and profile ratings, but automated online matchmaking, a synced game archive, multi-principal-variation analysis, and a curated puzzle collection are not implemented.

Full games support Studio step, slide, and leap movement; per-vector move, capture, and attack behavior; mirroring; jumping; range; and optional promotion. Royal custom pieces and custom king movement remain unsupported so standard check and castling rules stay reliable. A Studio piece replaces a non-king starting piece type for either or both sides. Variant bot turns use the rules-aware local search fallback instead of the standard-chess worker. With no-draw rules enabled, stalemate is a loss for the side with no legal moves.

## Sound files

The sound manifest maps `move-self.mp3`, `move-opponent.mp3`, `capture.mp3`, `move-check.mp3`, `castle.mp3`, `promote.mp3`, `game-start.mp3`, `tenseconds.mp3`, and `premove.mp3` to their corresponding move, capture, check, castle, promotion, start, clock-warning, and selection events. The settings dialog provides master/effects volume, mute, event toggles, and previews. Browser verification confirmed that all nine available previews started and ended; game-start, player/opponent moves, capture, check, castling, promotion, and the clock warning also played through their game-event routes. Volume, mute, and event-toggle changes persisted and were restored after testing. `game-end.webm` was not browser-decodable in the tested browser; there are no dedicated playable assets for checkmate, victory, defeat, draw, or puzzle outcomes, so those events are reported as unavailable instead of receiving substitute sounds.
